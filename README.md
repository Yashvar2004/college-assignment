# okDriver Command Center

A submission-ready prototype for centralized CCTV operations: camera onboarding, synthetic near-live feeds, health monitoring, ANPR ingestion, watchlist matching, GIS, WebSocket alerts, response workflows, vehicle movement, and audit history.

> All seeded people, identifiers, events, credentials, and feeds are synthetic. The animated feed adapter is clearly labeled and does not claim to be a physical live camera.

## What is implemented

- Admin/operator JWT authentication with Argon2 password hashing and backend RBAC
- Camera registry with search, onboarding, enable/disable, health states and protected endpoints
- Two-plus distinct animated synthetic camera feeds through a replaceable adapter boundary
- Leaflet/OpenStreetMap operational map with health and alert marker states
- Validated ANPR ingestion, number normalization, external-ID and 10-second temporal deduplication
- Active/valid watchlist matching and persisted real-time WebSocket alerts
- New → acknowledged → resolved response workflow with actor/timestamp metadata
- Chronological vehicle trace across three cameras with point-to-point polyline
- Searchable/paginated API resources and audit history
- PostgreSQL-compatible SQLAlchemy schema, indexes, Alembic, Redis-ready deployment, with reproducible synthetic MP4 assets
- Dockerfiles, health-checked Compose, seed/simulator tools, tests and CI

## Technology choices

React + TypeScript/Vite keeps the operator UI fast and small. FastAPI supplies validation and OpenAPI. SQLAlchemy/Alembic keep the schema RDS-compatible. PostgreSQL is authoritative; Redis is provisioned for scale-out fan-out/cache evolution while the single-node prototype broadcasts in process. Leaflet/OSM avoids a paid map key. Two original synthetic MP4 feeds are generated by `scripts/generate_demo_videos.py` and delivered through the recorded-file adapter.

## Fastest setup: Docker

Prerequisites: Docker Desktop with Compose.

```bash
cp .env.example .env
# Edit JWT_SECRET and POSTGRES_PASSWORD in .env
docker compose up --build
```

Migrations and idempotent demo seeding run when the API starts. Open:

- UI: http://localhost:8080
- Swagger: http://localhost:8000/docs
- Health: http://localhost:8000/health

Stop with `docker compose down`; add `-v` only when intentionally deleting local database/Redis volumes.

## Native development

```bash

# PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
alembic upgrade head
python -m app.seed
```

In another terminal:

```bash

```

The native default uses `apps/api/okdriver.db` for convenience. Docker uses PostgreSQL. Set `DATABASE_URL` to test another compatible database.

## Environment variables

Copy `.env.example`; never commit `.env`. Important values are `DATABASE_URL`, `REDIS_URL`, a random 32+ character `JWT_SECRET`, `CORS_ORIGINS`, `ACCESS_TOKEN_MINUTES`, `DEMO_MODE`, `VITE_API_URL`, and `VITE_WS_URL`. Stream secrets are stored only in the backend column and excluded from response schemas. In a real deployment, use a secrets manager and encrypted reference rather than a raw URL.

## Video assets and adapter

The seeded junction and RTO cameras use two distinct original MP4 assets under `apps/api/media`. They are served by the authenticated camera stream-discovery endpoint and played with a looping HTML5 video element. Regenerate them with the build-only dependencies in `scripts/requirements.txt`:

```bash
pip install -r scripts/requirements.txt
python scripts/generate_demo_videos.py
``` 

The adapter response deliberately identifies the feed as synthetic recorded media. Future RTSP/ONVIF/HLS/WebRTC adapters can replace the delivery URL without changing dashboard contracts.

## Generate a live demo event

With services running:

```bash
python scripts/simulate_events.py --vehicle GJ01XX0001
```

Or use Swagger: log in, copy the bearer token via **Authorize**, select a camera from `GET /api/v1/cameras`, then call `POST /api/v1/events/ingest`. A matching request is:

```json
{
  "external_event_id": "demo-unique-001",
  "camera_id": "<camera UUID>",
  "timestamp": "2026-09-26T10:00:00Z",
  "vehicle_number": "GJ-01-XX-0001",
  "confidence": 0.97,
  "vehicle_type": "car",
  "bounding_box": {"x": 0.2, "y": 0.3, "width": 0.4, "height": 0.3},
  "event_type": "anpr",
  "source_metadata": {"adapter": "swagger-demo", "synthetic": true}
}
```

Use a new external ID/timestamp on repeat runs. Duplicate IDs and same-camera/plate events in the same 10-second bucket return the existing event with `duplicate: true`.

## Security boundary

Local HTTP is intentional. TLS is **not** implemented by the app; production HTTPS/WSS terminates at an ingress/load balancer, with private service networking behind it. See [docs/SECURITY.md](docs/SECURITY.md).

## Known limitations

- Synthetic recorded MP4 feeds are demonstrations, not RTSP decoding or archive playback. The media adapter boundary is real and documented.
- The route connects observed coordinates; it is not road-network reconstruction.
- Single-process WebSocket broadcast is used. Redis is provisioned but a pub/sub bridge is the next step for multiple API replicas.
- Prototype login and ingestion endpoints have IP-based rate limits; production should add gateway identity quotas and Redis-backed distributed limits.
- No multitenant row-level isolation, evidence export, real camera discovery, object storage, or deployed TLS.
- Docker/FFmpeg were unavailable in the authoring environment; Compose is supplied but runtime validation must be repeated on a Docker host.

## Troubleshooting

- **401**: sign in again; tokens expire per `ACCESS_TOKEN_MINUTES`.
- **Map tiles blank**: OSM tiles require internet; markers and workflows remain functional.
- **Database not ready**: wait for Compose health checks, then inspect `docker compose logs db api`.
- **Port collision**: change published ports and update `VITE_API_URL`/`VITE_WS_URL` before rebuilding web.
- **No alert**: use active seeded plate `GJ01XX0001`, a unique event ID, and an enabled camera.
- **Stale native schema**: from `apps/api`, run `alembic upgrade head` and `python -m app.seed`.
